# Vsedi 開発日記

このディレクトリには、Vsedi の開発で行った指示・判断・作業・結果を、後から経緯を追える時系列ログとして記録する。

## 目的

- 後から「どの指示を受けて、何を判断し、何を変更したか」を追えるようにする
- Issue / PR / ADR だけでは見えにくい作業の流れを残す
- 次回の作業開始時に、直前までの状態を把握しやすくする

## 1日の区切り

日記上の1日は **05:00 から翌日 04:59 まで** とする。

例えば、2026-08-11 02:00 の作業は `2026-08-10.md` に記録し、2026-08-11 05:00 以降の作業は `2026-08-11.md` に記録する。

## ファイル名

1日につき1ファイルとし、05:00を開始時刻とする日付を使って次の形式で作成する。

```text
YYYY-MM-DD.md
```

例:

```text
2026-08-10.md
```

## 記録方法

**ユーザーからVsediに関する指示を受けるたびに、その日のファイルへ追記する。**

日末にまとめて要約するだけではなく、指示ごとの経緯が分かるように時系列で残す。

各エントリには、可能な範囲で次を記録する。

- 時刻
- ユーザーの指示・質問
- 判断した内容
- 実際に行った変更・確認
- 作成・更新・マージした Issue / PR / ADR
- 未解決事項や次の作業

推奨形式:

```markdown
## HH:MM — 短い見出し

### 指示

ユーザーから受けた指示を簡潔に記録する。

### 対応

実際に行った作業や判断を記録する。

### 結果

Issue / PR / commit 等の結果を記録する。
```

## 方針

- 日記は設計仕様の正本にはしない
- 正式な設計判断は ADR、要件は `docs/development/requirements.md`、計画は `docs/development/roadmap.md`、実作業は Issue / PR を正本とする
- 日記には、それらへの参照と作業経緯を残す
- 過去の記録を後から都合よく書き換えず、方針変更や前言撤回も新しいエントリとして残す
- 秘密情報、credential、token、password 等は記録しない
- 事実誤認を訂正する場合も、何を訂正したかが分かる形で記録する
