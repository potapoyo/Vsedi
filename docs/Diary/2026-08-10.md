# 2026-08-10

## 今日行ったこと

Vsedi の実装開始前に、製品・安全性・開発基盤に関する設計を整理し、GitHub 上の ADR / Issue / PR へ反映した。

### 製品・基盤方針

- Vsedi を「VRChat Unity プロジェクトの安全なセーブ・履歴・復元ツール」として整理した
- Tauri v2 をデスクトップ基盤として採用した
- Windows と Apple Silicon macOS を正式対応対象とした
- 初期配布は未署名とし、Windows installer / macOS DMG を最終的な配布物とする方針を整理した
- Frontend を React + TypeScript + Vite + pnpm + Tailwind CSS + shadcn/ui とした
- Rust を共有型の正本とし、`serde + ts-rs` で TypeScript 型を生成する方針を確定した

### 設定・復旧

- アプリ内部設定と持ち運び可能な環境バックアップを分離した
- 内部設定は `settings.json`、整数の `schemaVersion` を持つ方針とした
- 環境バックアップは `vsedi-environment.vsedi.json`、整数の `formatVersion` を持つ方針とした
- 設定破損時は、元ファイルを黙って上書きせず「保全 → migration → 最後に再生成」の順で扱う方針を確定した
- PC 故障時には、理解しているユーザーが `settings.json` を所定位置へ手動配置して低レベル復旧できる余地を残した

### Git / Git LFS

- Git は system Git CLI を Rust 側から利用する方針を維持した
- Git LFS は `git-lfs` executable を独立探索せず、Vsedi が利用する Git に対する `git lfs version` で診断する方針を確定した
- Git / Git LFS の未導入は可能な限りエラーではなく通常の診断状態として返すことにした

### エラー処理

- 共通 `AppError` / `ErrorCode` モデルを確定した
- Frontend は Git stderr / OS error の文字列解析で UI 分岐しない方針とした
- mutation の途中失敗では `mayHaveMutated` を使って状態変更可能性を表現することにした

### ログ

- application logging の方針を確定した
- 日次ローテーションとした
- ログ保持期間を **30日** とした
- 通常は `INFO` 以上、`DEBUG` は明示的に有効化する方針とした
- credential / token / password 等をログへ記録しないことを明記した
- remote URL は sanitize し、診断ログ export 時には project path 等の個人環境情報を匿名化する方針とした

### Rust 構成と生成型

Rust 側は次を基本 module とする方針を確定した。

```text
commands/
services/
git/
platform/
models/
errors/
logging/
settings/
```

- Tauri command は薄く保つ
- application use case は service layer に置く
- Git / OS / settings の実処理はそれぞれの module へ分離する
- Unity / VRChat 固有 module は必要になる milestone で追加する
- `ts-rs` の生成済み TypeScript 型は Git 管理する
- CI で型を再生成し、差分がないことを確認する方針とした
