## 12:45 — LFS診断・Git境界・VPM追跡方針を変更

### 指示

- Git LFSを必要と感じていないため、Vsediでは確認しない方針にする
- Unity project以外の関連ファイルを同じrepositoryで保存するため、Git rootがUnity project外にある状態を修正対象にせずINFO表示にする
- VPM package本体をGit管理に含めるかどうかを設定で変更可能にする

### 対応

- Git LFSの導入診断、UIカード、`.gitattributes` LFS rule、大容量ファイル候補の診断を削除した
- Git repository rootがUnity project外にある診断をWARNINGからINFOへ変更し、「要修正」の理由に含めないようにした
- `VpmTrackingPolicy` を追加し、「VPM packageを除外」「VPM packageを含める」をUIから切り替えられるようにした
- 公式デフォルトに合わせて初期値を「除外」とし、選択した方針と `.gitignore` / Git追跡状態が矛盾する場合だけ警告するようにした
- `settings.json` のschemaを2へ更新し、schema 1からVPM追跡方針を補うmigrationを追加した
- ADR 0012を追加し、要件、ロードマップ、アーキテクチャ、既存ADR、READMEを新方針へ更新した

### 結果

- `cargo test --manifest-path src-tauri/Cargo.toml` 成功（18 passed, 0 failed）
- `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings` 成功
- TypeScript型検査、Vite production build、`git diff --check` 成功
- 実機GUIでのVPM設定切替確認は未実施

## 01:20 — M2実機GUIテストを別PCへ引き継ぎ

### 指示

- M2がmainへマージ済みであることをpull後に確認する
- Macのロック解除後にM2の未確認GUI項目をテストする
- 別PCで続行できるよう、テスト内容を記録する

### 今回の確認

- `main` を `origin/main` へfast-forwardし、PR #16のmerge commit `e8dc4c4` とM2先端 `72acb06` がmainに含まれることを確認した
- `mise trust` 後、固定toolchainのNode.js `22.23.1`、Rust / Cargo `1.97.1`、pnpm `11.16.0`を利用可能にした
- `mise exec -- pnpm tauri dev` でVite起動、Rust compile、`target/debug/vsedi` 起動まで成功した
- Computer UseのGUI状態取得がVsediだけでなくFinder等でもtimeoutし、画面の読取・操作へ進めなかった
- 起動processは終了済みで、Gitの作業treeはcleanのままである

### 別PCでの開始手順

1. `main` を最新化し、`git log -1 --oneline` が `e8dc4c4` 以降であることを確認する
2. 必要な場合は `mise trust`、`mise install`、`pnpm install --frozen-lockfile` を実行する
3. repository rootで `pnpm tauri dev` を実行する
4. Vsediのnative windowが開いたら、以下のGUIテストを順番に実施する
5. 各項目の結果を本Diaryへ追記し、失敗時は画面表示、再現手順、該当する診断code、診断logを記録する

### M2 GUIテスト項目

#### 1. 起動と環境診断

- Vsediのnative windowが開く
- 「実行環境」が「対応対象」になり、実行OSとarchitectureが正しく表示される
- 「System Git」が「利用可能」になり、Git versionが表示される
- 「再診断」を押しても赤いerrorが出ず、表示が更新される

#### 2. Unity / VRChat project診断

- 「フォルダを選択」からUnity project rootを選択できる
- project path、Unity version / revision、診断状態が表示される
- VRChat Avatar projectでは「VRChat Avatar」と関連packageが表示される
- VRChat World projectでは「VRChat World」と関連packageが表示される
- 非Unity folderでは「非 Unity」と不足理由が表示され、アプリが停止しない
- Git repositoryのないproject、project自身がGit rootの構成、親folderがGit rootの構成をそれぞれ診断できる
- Git rootがUnity projectの親にある構成はINFO相当で扱われ、それだけで「要修正」にならない
- Git rootのpathやstatus pillは主要UIに表示されない

#### 3. source-control診断とVPM追跡方針

- `.gitignore` とVPM packagesの診断summaryが表示される
- 「VPM packageのGit管理」を「除外する」へ切り替えると、除外方針に基づいて診断が更新される
- 「含める」へ切り替えると、追跡方針に基づいて診断が更新される
- 切替後にprojectを再選択またはアプリを再起動しても、選択した方針が保持される
- 選択方針と`.gitignore` / Git追跡状態が一致すれば正常、一致しなければ警告になる

#### 4. 非対応projectと読取警告

- Avatar SDKとWorlds SDKが同居するprojectを選ぶと、`PROJECT_UNSUPPORTED_KIND` と安全な説明が表示され、通常の管理対象として登録されない
- `ProjectSettings/ProjectVersion.txt`を読み取れない場合、読取警告を表示し、可能な範囲の診断は継続する
- `Packages/manifest.json`または`Packages/vpm-manifest.json`を読み取れない場合、package manifestの警告を表示し、アプリが停止しない
- `.gitignore`または`Packages/.gitignore`を読み取れない場合、source-control警告を表示し、アプリが停止しない
- テストのためにpermissionを変更したfileは、確認後に元のpermissionへ戻す

#### 5. 最近のproject

- 選択したprojectが「最近の project」へ表示される
- アプリ再起動後も最近のprojectが復元される
- pathが存在しなくなったprojectは削除されず「再指定」と表示される

#### 6. ログ別ウィンドウ

- 「ログ表示」を押すと、`logs`のnative別windowが開く
- window内に`VSEDI DIAGNOSTICS`や「リアルタイムログ」の余分な見出しが表示されない
- 「1秒ごとに最新ログを読み込みます。現在のファイル: ...」の補足が表示される
- 最新logが表示され、約1秒間隔で更新され、末尾へ追従する
- 「ログ表示」を再度押してもwindowが増殖せず、既存windowが前面へ出る
- アプリ内の「閉じる」buttonはなく、macOS / Windows標準のwindow close操作で閉じられる
- close後に「ログ表示」を押すと再度開ける

#### 7. ログfolderとexport

- 「ログフォルダ」を押すと、macOSではFinder、WindowsではExplorerで実際のlog directoryが開く
- macOSで`The application cannot be opened because its executable is missing.`が再発しない
- 「診断ログを書き出す」で保存先を選択でき、sanitizedされたlog fileが生成される
- exportしたlogにcredential付きURL、secret、user home directoryの未加工値が含まれない

### 合格条件

- 上記の通常操作でクラッシュや操作不能が発生しない
- userが次に行動できる未検出・要確認状態は診断結果として表示される
- command自体の失敗だけが構造化errorとして表示される
- VPM方針変更、最近のproject、log windowの再openが期待どおり保持・更新される
- 不合格項目がある場合はM3へ進む前に、再現fixtureと修正範囲をIssueまたはDiaryへ記録する
